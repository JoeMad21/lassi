## Scope

P12 builds what the P12 row of the bible's Build Roadmap names (verbatim): "Python subset, Rust MIR, C# Roslyn, Fortran, LLVM import; harness bindings per language". That is the Language Frontends rows for Python's scalar and NumPy kernels, Rust, C#, Fortran, and any LLVM language, each a Frontend behind the interface that exists since P0 (Component Interfaces; lassi/core/interfaces.py, Frontend.raise_source), tagged by the Frontend Rules; the bindings that the Frontend Rules and Repository Layout (assets/harness/) name beside lassi_io.h; the native toolchains each language's oracle runs need (Frontend Rules, native execution path); and xlang-v0, the suite the gate reads (Benchmark Suites). Out: Python tensor code (its Language Frontends row), ClangIR, the C and C++ frontends and the CPU target (P5.7), any stage that asks a model (P6), cgeist's CUDA path unless the owner places it here (OQ-058), xDSL unless the owner pins it here (OQ-059), and the Numba fallback of the Python scalar and NumPy row, since Numba's LLVM IR comes from llvmlite's own LLVM, a third LLVM that the frontend pin rule below sends to the owner queue, and the gate needs only the subset frontend.

Gate (the P12 row's Gate column, verbatim): "xlang-v0 programs raise to the hub and round-trip natively in every language". It names no device and no owner review, so a pass sets P12 DONE. Relation to other phases: the hub's verifier, normalize, and CPU lowering are P5's (P5.6, the cpu-mlir IRLevel at Polygeist's LLVM; P5.7, the C and C++ frontends and the CPU target), so every P12 round trip depends on them, and P12.12 extends P5.12's round-trip driver in `lassi corpus`. P5.12 brings its own dependencies (plans/STATUS.md): P5.8, P5.9, and P5.10, P5's Tenstorrent raiser, program spec, and target on ttsim (P5.12 needs P5.10, which needs P5.9, which needs P5.8), beside P5.4, and through it P5.17, which P5.6 already needs; so P12's CPU-only gate waits for P5's Tenstorrent chain too, and for the owner if P5.12 goes OWNER on a Tier A reference beyond cgeist's reach (plans/p5-ir.md, P5.7). P11 runs beside P12 (AGENTS.md, Work Order); P13 owns xDSL's csl use; P16's part (a) follows P12; P6 binds frontends in its MLIR-level stages later.
