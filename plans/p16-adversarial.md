Decisions taken at planning (the named task records each in the bible with a Decision Log entry):

- Input contract (P16.1). An item's contract is its held-out input spec read as one (Benchmark Suites, Held-out inputs): each input's name, dtype, and shape, and every element in [lo, hi), unless the item declares the optional manifest key P16.1 defines. A proposal outside it is refused before any run and counted.
- Confirmed divergence (P16.5). On an accepted proposal the target reference's run is clean with readable outputs and binary_io fails an output of the candidate's run. The target reference stands in for the source program: Adversarial Setups item 1 reads "divergence between source and candidate outputs", but the source never runs on some directions (TT -> C++ with baseline_both off), so P16.5's edit of item 1 records the change, and P16.9's results say a Tier A divergence is measured against the C++ reference only. A reference that fails on an in-contract input is a contract finding, recorded under its own code, never a divergence. The threshold is the recipe's binary_io metric and threshold; P16's recipes give a number, and under from_baseline it is the item's declared tolerance, since the references' agreement was measured on the held-out inputs only.
- Gate subjects (P16.8). No suite holds faulty candidates, so the base set is written here: small deterministic C++ reference programs in a new suite (proposed adv-seeded-v0, every item unassigned until OQ-067's split answer), run cpp -> cpp, and seeded faulty variants kept as replay fixtures outside every suite. OQ-067 asks whether Tier A's C++ side joins (P16.9).
- Freeze (P16.10). Before any adversary-stage run reads adv-seeded-v0 or a Tier A item, exploratory runs included, a committed freeze record (proposed tests/fixtures/adversary/freeze.yaml) fixes the sha256 of every seeded candidate and witness, of the fuzzer's and the llm adversary's source files, of adversary-v0's prompts and the adversary recordings, and each gate recipe's adversary seed and budget and oracle threshold; a fast test fails on any difference. A candidate is fixed only on its witness checks, which run no adversary, and is re-hashed before the record is written. After the first adversary run on a set, nothing in the record changes in response to any run on it: a fix that changes an adversary, a candidate, or a recorded value is measured only on a fresh seeded set (proposed adv-seeded-v1) written after the change and frozen before the changed adversary first runs on it, or goes to the owner. Witnesses are written from each fault's trigger condition, recorded in the index, never from the fuzzer's strategies or proposals.
- Gate reading (P16.G). For every seeded candidate, a `lassi run` delivers it as the replay backend's reply (bound by model.recording, P16.13; synthetic, never model output); it passes binary_io on the item's held-out inputs in that run, so the divergence is the adversary's finding, not the held-out inputs'; and the fuzzer, within the recipe's budget, finds at least one oracle-confirmed divergence. Every control (each reference as its own candidate, through the mock) gets none. Every out-of-contract proposal, those of a replay-driven llm adversary written to break the contract included, is refused before any run. A candidate is never changed or dropped after any adversary run reads it; a miss is reported and adds fix tasks under the Freeze decision.
