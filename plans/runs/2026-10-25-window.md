## The Plan

One big job, started at 08:00 from a clean commit in its own slot, which needs no session once started; its rx
timeout ends it at the window's end, and its deadline is 14:45 EDT:

```
PYTHONIOENCODING=utf-8 uv run tools/rx.py job start --big --slot window --name window --timeout <seconds to 15:00> -- \
  'bash plans/runs/window/run-all.sh <14:45 EDT as epoch seconds>'
```

- Training first, in the background (plans/runs/train-window/run.sh): the four tt-train-v0 recipes on alpha01's CPU,
  64 threads, each started only while the time left covers its PROJECTED estimate.
- Downloads: furiosa-ai/gpt-oss-20b (14.59 GB at v2026.4) with 80 GB free, then furiosa-ai/gpt-oss-120b (68.12 GB) in
  the background with 140 GB free, each the RNGD build only, the sums of the tag's root files in
  https://huggingface.co/api/models/furiosa-ai/<model>/tree/v2026.4, read 2026-10-25, the thresholds keeping the gate's 60 GB floor for big jobs and a margin on the shared disk. The last
  reading had 117.1 GB free (results/rngd-matrix-short-20261024/provenance.json), so gpt-oss-120b will most likely be
  skipped; OQ-081 asks the owner which cached weights may go to make room.
- The feature matrix (plans/runs/rngd-sweep/matrix.sh) over models7.tsv, one model at a time on port 8123:
  gpt-oss-20b (1 card), Qwen3-Coder-30B (4), gpt-oss-120b (4, if downloaded), EXAONE-4.0-32B (4). Each runs the 8
  combinations of the API reference, retrieval, and the coarse mismatch report at two tolerance halves (16 recipes),
  and one more combination, mmapiragrl, every feature with a restart after 4 failed corrections in a row (P17.25)
  and the pack's declarations before each compile correction (P17.26), at both halves (18 recipes side by side),
  cpp -> tt, the fuzzer in all, cap 15. GPT-OSS runs at the server's default reasoning effort (OQ-080) with a budget
  of 16384 tokens. The time left is shared among the models still to run. Every TT program runs on ttsim, a simulator.
- Stop early: create $LASSI_RUNS_ROOT/rngd-sweep/STOP with one `rx exec`; run.sh stops before the next model.

Not in this window: model output on the Wormhole cards (OQ-078; the tt_silicon executor, P17.16, is not built).
